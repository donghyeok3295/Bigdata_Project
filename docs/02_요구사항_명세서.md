### 3.3 로딩과 라벨 코호트 제외 규칙

**로딩**: 전 컬럼 문자열로 읽고 `na_values=["\\N", ""]` 적용. 시각은 `zfill(6)` 후 일자와 결합해 파싱.

**제외 (순서대로, 건수 기록)**

1. `trmn_type`이 취소
2. `dclr_ts` 또는 `arvl_ts` 결측
3. `resp_min <= 0` 또는 시각 역전
4. `resp_min > 180` (명백한 입력 오류)

60~180분 기록은 유지한다(FR-M-09로 민감도 확인).

**`dist_km` 이상치 (D-009)**: 음수(2024년 4건)와 **100km 초과(15건, 최댓값 2024km)** 는 명백한 입력 오류다. **행을 제외하지 않고 `dist_km`만 결측 처리**한다 — 라벨(`resp_min`)은 정상이므로 코호트에서 뺄 이유가 없고, D− 설정에서는 거리를 쓰지 않으므로 그대로 사용한다. 6km(상위 1%) 초과는 오류가 아니라 `out_of_range` 표시 대상이므로 **유지**한다.

**2024년 실측 적용 결과** (서울 585,503건 기준)

| 규칙 | 제외 건수 |
| --- | --- |
| 취소 | 9,672 |
| 도착 기록 없음 (결측·공백 문자) | 25,099 |
| 0분 이하·시각 역전 | 118 |
| 180분 초과 | 363 |
| **남은 분석 대상** | **550,251 (94.0%)** |

도착 기록 없음 25,099건은 종결구분이 "정상"인 경우가 다수이며 출동 시각은 모두 존재한다. 미이송·현장 종결로 도착 기록이 남지 않은 것으로 보인다.

| --- | --- |
| `city_calls_60` | 서울 전체에서 `dclr_ts ∈ [t−60분, t)`인 신고 건수 (취소 포함) |
| `sgg_calls_60` | 같은 `sgg`에서 `dclr_ts ∈ [t−60분, t)`인 신고 건수 |
| `sgg_dspt_60` | 같은 `sgg`에서 `dspt_ts ∈ [t−60분, t)`인 출동 건수 |
| `center_dspt_60` | 같은 `center_id`에서 `dspt_ts ∈ [t−60분, t)`인 출동 건수 |

`out_of_jur`는 시간창과 무관한 **정적 피처**다.

| 피처 | 정의 |
| --- | --- |
| `center_sgg` | 출동 센터가 **소재한** 구. 안전센터 현황(공공데이터포털 15157581)의 `위치` 컬럼 첫 토큰에서 추출. 서울 안전센터 119개가 `center_id`와 100% 매칭됨 |
| `out_of_jur` | `sgg_nm != center_sgg`이면 1 (관외출동). 센터 위치는 고정값이고 신고 구는 t 시점에 알 수 있으므로 **누출 없음** |

주의: `sgg_nm`은 **신고 위치**의 구이지 센터 소속 구가 아니다. 두 값을 혼동하면 `out_of_jur`가 항상 0이 된다.

```python
def count_window(events, queries, keys, ev_col):
    """keys 기준으로 [t-60m, t) 구간의 events 수를 센다."""
    ev = events.select(*keys, F.col(ev_col).alias("ev_ts")).where("ev_ts is not null")
    return (
        queries.join(ev, keys)
        .where(
            (F.col("ev_ts") >= F.col("t") - F.expr("INTERVAL 60 MINUTES"))
            & (F.col("ev_ts") < F.col("t"))
        )
        .groupBy("call_id")
        .count()
    )
```

도시 단위는 파티션이 한쪽으로 몰리지 않도록 날짜별로 나눠 계산한다.

### 3.5 복귀 일시와 복귀 전 출동기록 (조건부)

- `cbk_ymd`가 있으면 사용. 없으면 출동일 + `cbk_tm`, `cbk_tm < dspt_tm`이면 다음 날
- 출동~복귀 12시간 초과는 복원 실패(null)
- **복원 가능률 90% 이상일 때만** `open_dspt_at_t`(같은 센터에서 `dspt_ts < t < cbk_ts`인 다른 기록 수) 사용 (D-004)
- 명칭은 "복귀 전 출동기록 수". 구급차 수로 부르지 않는다

### 3.6 정체 지수

- 차량통행속도 도로를 구에 매핑 → `speed_hist`(구·시간 평균 속도)
- `speed_norm`: **학습 기간**의 구 × 요일유형(평일/주말·공휴일) × 시간대 평균
- `cong_idx(t) = speed_hist(구, 직전 시간) / speed_norm(구, 요일유형, 시간대)` — 1보다 작으면 평소보다 막힘
- 자료 없는 시간대는 `cong_idx = 1`, `cong_missing = 1`
- 실시간: 수집된 실시간 속도를 **같은 도로 목록·같은 구 매핑·같은 함수**로 계산. 도로 범위 차이는 D-005에 기록
- 원본은 링크 단위다. 구 평균과 별도로 링크 속도를 3.8절 경로 예상 시간에 쓴다

### 3.7 기상 (D-012, D-013)

- ASOS 108 시간자료. 학습 피처는 **3시간 블록 누적 강수 `rain_3h_mm`**: 3시간 정시(00·03·06시…)마다 직전 3시간 누적. 4~10월은 시간 값 3개의 합, 겨울(11~3월)은 정시 값(이미 3시간 누적)
- 신고 시각 `t`에는 **`t`보다 공개 지연(60분) 이상 앞서 끝난 가장 최근 블록**만 붙인다. 학습·서비스 같은 함수(`latest_block_end`). 지연 값은 `configs/data.yaml`, 초단기실황 실제 공개 시각 확인 후 조정
- **빈칸과 QC 9는 무강수**다. 일강수량과 대조해 확인했다(시간 합 = 일강수량 99.95%, 2019~2024). `rain_missing`·`rain_3h_missing`은 원본 행이 없거나 QC 1(오류)인 경우만 1이다 (현재 0건)
- 0.0mm(미량)와 빈칸은 구분하지 않고 무강수로 합친다 (한계)
- 계절 경계는 기상청 하루(01~24시) 기준: 00시 값은 전날로 본다
- 적설은 실시간 API에 대응 값이 없어 서비스 모델에는 쓰지 않는다. 분석 전용 비교 모델에서만 쓴다. 적설 빈칸은 무적설 (지침 5.2.2)
- 실시간: 초단기실황 1시간 강수량(RN1)을 3시간 블록으로 모아 같은 정의로 만든다. 실패 시 `rain_3h_mm=0` + 경고

### 3.8 경로 기반 예상 시간 (D-010)

- 후보는 `unit_type = center`만, 직선거리 기준 5곳 + 관할 센터(5곳 밖이어도 포함)
- `location.hdong`·`bdong`: 신고 지점의 행정동·법정동. `jurisdiction`: `{center_ids, status: "single"|"multiple"|"unknown", matched_dong, split_by_lot}`. `candidates[].is_jurisdiction`: 관할 센터 여부. 관할 판정은 화면 표시용이며 모델 입력(`out_of_jur`, 구 기준)과 무관 (D-011)
- `dist_km`: 센터 → 입력 좌표의 도로 최단거리를 정수 km로 반올림
- `out_of_range`: 거리 상위 1% 초과 시 true, 화면에 "학습 범위 밖" 표시
- 순위는 `p_ontime`으로만 정한다. `route_eta_*`는 G6 모델 입력값(역추적 함수), `route`는 입력 좌표까지의 실제 경로로 화면 설명용 (D-010)

- `route.breakdown`: 같은 경로를 ① 평소 속도 ② 현재 속도 ③ 현재 속도 + 특례로 계산한 차이. 불법주정차는 향후 계획
- `route.segments`: 도로 구간별 현재/평소 속도 비(`speed_ratio`), 지도 색칠용. `route.general`: 일반 차량 기준 경로가 구급차 경로와 다를 때만(우회)
- 좌표 배열은 `[lat, lon]` 순서. 경로 계산 실패 시 `route = null` + `warnings`
- `route.segments`의 첫·마지막 구간은 센터·신고 지점에서 가장 가까운 도로까지의 진입 구간(`access: true`)
