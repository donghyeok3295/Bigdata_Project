### 3.3 로딩과 라벨 코호트 제외 규칙

**로딩**: 전 컬럼 문자열로 읽고 `na_values=["\\N", ""]` 적용. 시각은 `zfill(6)` 후 일자와 결합해 파싱.

**제외 (순서대로, 건수 기록)**

1. `trmn_type`이 취소
2. `dclr_ts` 또는 `arvl_ts` 결측
3. `resp_min <= 0` 또는 시각 역전
4. `resp_min > 180` (명백한 입력 오류)

60~180분 기록은 유지한다(FR-M-09로 민감도 확인). `dist_km` 결측은 D+ 설정에서만 제외한다.

### 3.4 활동량 (전체 기록 표 `ems_seoul_all`에서 계산)

t = 코호트 각 건의 `dclr_ts`, 자기 자신 제외.

| 피처 | 정의 |
| --- | --- |
| `city_calls_60` | 서울 전체에서 `dclr_ts ∈ [t−60분, t)`인 신고 건수 (취소 포함) |
| `sgg_calls_60` | 같은 `sgg`에서 `dclr_ts ∈ [t−60분, t)`인 신고 건수 |
| `sgg_dspt_60` | 같은 `sgg`에서 `dspt_ts ∈ [t−60분, t)`인 출동 건수 |
| `center_dspt_60` | 같은 `center_id`에서 `dspt_ts ∈ [t−60분, t)`인 출동 건수 |

```python
def count_window(events, queries, keys, ev_col):
    """keys 기준으로 [t-60m, t) 구간의 events 수를 센다."""
    ev = events.select(*keys, F.col(ev_col).alias("ev_ts")).where("ev_ts is not null")
    return (queries.join(ev, keys)
            .where((F.col("ev_ts") >= F.col("t") - F.expr("INTERVAL 60 MINUTES"))
                   & (F.col("ev_ts") < F.col("t")))
            .groupBy("call_id").count())
```

도시 단위는 파티션이 한쪽으로 몰리지 않도록 날짜별로 나눠 계산한다.

### 3.5 복귀 일시와 복귀 전 출동기록 (조건부)

- `cbk_ymd`가 있으면 사용. 없으면 출동일 + `cbk_tm`, `cbk_tm < dspt_tm`이면 다음 날
- 출동~복귀 12시간 초과는 복원 실패(null)
- **복원 가능률 90% 이상일 때만** `open_dspt_at_t`(같은 센터에서 `dspt_ts < t < cbk_ts`인 다른 기록 수) 사용 (D-004)
- 명칭은 "복귀 전 출동기록 수". 구급차 수로 부르지 않는다

### 3.6 정체 지수

- 차량통행속도 도로를 구에 매핑 → `speed_hist`(구·시간 평균 속도)
- `speed_norm`: **학습 기간**의 구 × 요일유형(평일/주말·공휴일) × 시간대 평균
- `cong_idx(t) = speed_hist(구, 직전 시간) / speed_norm(구, 요일유형, 시간대)` — 1보다 작으면 평소보다 막힘
- 자료 없는 시간대는 `cong_idx = 1`, `cong_missing = 1`
- 실시간: 수집된 실시간 속도를 **같은 도로 목록·같은 구 매핑·같은 함수**로 계산. 도로 범위 차이는 D-005에 기록

### 3.7 기상

- ASOS 108 시간자료 강수량, 신고 시각의 **직전 정시**
- 빈칸을 바로 0으로 채우지 않는다. 품질 표기로 무강수와 결측을 구분하고 결측은 `rain_missing = 1`
- 적설은 실시간 API와 정의가 달라 사용하지 않는다
- 실시간: 초단기실황 1시간 강수량(RN1), ASOS 108 위치 격자

| G4 | G1 + 구·센터 활동량 + 정체 지수 |
| 단순 기준 | 학습 구간 센터×시간대 지연율, 50건 미만은 센터 평균 → 전체 평균 |
| LightGBM | 가중치 없음, 범주형 직접 입력, 검증 구간 조기 종료, **모델별 동일 예산 튜닝**(같은 탐색 공간, 같은 시행 횟수, 시드 42) |
| LR·B0 | 수치 표준화, 범주 원-핫, 가중치 없음 |
| 보정 | 보정 구간으로 isotonic(표본 충분) 또는 Platt. 보정기를 모델과 함께 저장 |
| 주 지표 | Brier, log loss, calibration slope·intercept |
| 보조 지표 | ROC-AUC, AP. **ΔAUC 0.005 미만은 실질적 차이로 해석하지 않는다** |
| 검정 | 시험 구간 날짜 블록 부트스트랩 1,000회, G1과 같은 재표본에서 비교. 주 블록 민감도 |
| 산출물 | `models/{name}/{dplus|dminus}/{run_id}/model.txt, calibrator.pkl, features.json, params.json, threshold.json, metrics.json` |

## 5. API 명세

### 5.1 `POST /risk`

```json
{"center_id": "○○소방서 ○○119안전센터", "sgg": "○○구",
 "timestamp": "2026-11-20T18:30:00+09:00", "dist_km": 2,
 "center_dspt_60": 2, "sgg_calls_60": null, "sgg_dspt_60": null,
 "city_calls_60": null, "rain_mm": null, "cong_idx": null}
```
null이면: `rain_mm`·`cong_idx`는 실시간 값, 활동량은 같은 요일유형·시간대 학습 중앙값.

```json
{"p_ontime": 0.62, "risk_level": "주의",
 "top_factors": [{"feature": "sgg_dspt_60", "value": 14, "direction": "위험 증가"}],
 "inputs_used": {"rain_mm": 3.0, "cong_idx": 0.82, "source": "live"},
 "model": "G4/dplus", "disclaimer": "연구용 위험 비교이며 실제 출동 지령에 사용하지 않습니다."}
```

### 5.2 `POST /compare`

```json
{"lat": 37.5, "lon": 127.0, "address": null, "timestamp": null,
 "center_activity": {"○○소방서 ○○119안전센터": 3}, "mode": "slider"}
```

```json
{"location": {"lat": 37.5, "lon": 127.0, "sgg": "○○구"},
 "live": {"rain_mm": 0.0, "cong_idx": 0.78, "source": "live"},
 "candidates": [
   {"rank": 1, "center_id": "…", "p_ontime": 0.72, "dist_km": 2,
    "out_of_range": false,
    "route": {"eta_min": 6.2, "geometry": [[37.5, 127.0]],
              "contraflow_used": true, "parking_hotspots": 1}}],
 "nearest_center_id": "…", "warnings": [], "disclaimer": "…"}
```

- 후보는 `unit_type = center`만, 직선거리 기준 5곳
- `dist_km`: 센터 → 입력 좌표의 도로 최단거리를 정수 km로 반올림
- `out_of_range`: 거리 상위 1% 초과 시 true, 화면에 "학습 범위 밖" 표시
- 순위는 `p_ontime`으로만 정하고 `route`는 참고 정보

### 5.3 오류

| 상황 | 처리 |
| --- | --- |
| 서울 밖 위치, 지오코딩 실패 | 400 |
| 실시간 교통·기상 실패 | 200, 평소값(`cong_idx=1`, `rain_mm=0`)으로 계산하고 `warnings` 표시 |
| 후보 전원 `out_of_range` | 200, 순위 표시하되 경고 강조 |
