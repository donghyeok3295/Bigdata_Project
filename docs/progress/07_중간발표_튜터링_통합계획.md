날짜: 2026-10-25

## 끝낸 것

1. **튜터링 파이프라인을 프로젝트 설계 기준으로 정렬**: 활동계획서의 Kafka·Elastic Stack·MapReduce는 쓰지 않는다. 수집은 공공 API 수집기, 처리는 Spark 배치·Structured Streaming, 시각화는 Python 그래프·웹 화면. 튜터링 최종 발표에서 "계획 대비 변경"으로 설명한다 (`기업튜터링/00_현황정리.md` 0절)
2. **튜터링 계획 대비 구현 차이 분석**: 10회 중 차이 없음 4(1·4·5·9회), 일부 3(2·6·10회), 큼 3(3·7·8회). 계획·분석 단계는 계획대로, 실제 파이프라인 구현 단계가 밀려 있다
3. **튜터링 남은 구현과 중간발표 필수 작업이 거의 같음을 확인** (아래 표)
4. LightGBM 4.7.0 설치 (Python 3.12)

## 개발 방식

1. **진행표 작업 하나 = 결과물(그래프·표) 하나**로 끝낸다. 결과물은 중간발표와 튜터링 PPT에 같이 쓴다
2. 그래프는 노트북(`notebooks/`)에서 만들고 `eda/` 또는 `results/`에 저장한다. 수치는 스크립트 실행 결과만 쓴다
3. 코드는 `src/` 모듈 + 합성 샘플 테스트. 작업이 끝날 때마다 `ruff check .`, `pytest`
4. 10.28까지 못 만든 것은 튜터링 PPT에서 **목업 화면을 프로토타입으로** 보여 주고 향후 계획으로 표시한다(가상 값 명시)
5. 시험 구간(2025)은 열지 않는다. 모델 결과는 검증 구간 기준 **예비 결과**로 표시한다
