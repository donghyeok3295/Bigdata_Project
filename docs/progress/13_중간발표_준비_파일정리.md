## 끝낸 것

### 1. 중간발표 구성 (팀원 PPT 제작용)
- **확정 구성은 Notion「중간발표 최종 정리」**(빅데이터 팀 프로젝트 > 발표 > 중간발표). 5분, 본문 9장(S1~S9).
  - 흐름: 연구 질문(Q0·Q1·Q2) → 질문별 데이터·기초통계 → 질문에 맞춘 전처리 → 질문별 EDA → 모델·분할 → 1차 결과·실험 계획 → 일정·소논문·목업 시연 → R&R·산출물 → 타이타닉 과제(별도 보고, 프로젝트와 엮지 않음)
  - 슬라이드마다 "슬라이드에 넣을 자료"·"추가 자료(백업)" 토글에 그래프를 올리고, 그래프 설명 표와 발표 멘트, 질문 대비 표를 붙였다.
- 저장소 쪽 상세 설명: `발표자료/중간발표/01_팀원공유_프로젝트설명_발표목차.md`(프로젝트 설명, 단계별 기술·상태, 분할·학습 방법, 질문 대비). 5분 구성과 다른 부분은 Notion이 우선.
- 모델 근거는 **Hill et al. (2025)**(기획서 4절 서지 그대로). 추계학술대회 논문은 모델 근거로 쓰지 않고, 소논문 일정에서 "연구 제안 → 실제 실험"으로만 언급한다. 평가는 기존 계획대로 Brier·log loss.

### 2. 분할·학습 방법 정리 (교수님 피드백 "8:1:2, 섞어 가며 학습" 대응)
- 2025 안전센터 건수를 서버 Spark로 셈(라벨·성능은 보지 않음): 518,030건 중 **517,895건**.
- 분할 비율: 학습 2019–22 1,275,974(46.50%) / 검증 2023 421,592(15.36%) / 보정 2024 528,744(19.27%) / 시험 2025 517,895(18.87%), 합계 2,744,205.
- 8:1:1 무작위가 아닌 이유(보정 구간 필요, 같은 시간대 정보 공유로 누출, 연도별 분포 이동)와 **롤링(확장 윈도) 검증 4회안**을 문서·Notion에 적었다. 롤링 검증은 평가 설계 변경이라 **팀 합의 전**.
- 변수 추가 시 평가: 모든 단계를 같은 구간·같은 행·같은 튜닝 횟수로 돌려 G0 대비 ΔBrier, 2024 + 날짜 블록 신뢰구간, 최종은 2025에서 1회.

### 3. 노트북·그림
- `notebooks/09_중간발표_기초통계.ipynb`(신규): 분할별·연도별·질문별 변수 기초통계(`발표자료/중간발표/표/기초통계_*.csv`), 질문별 변수 분포(`2-8`), 기초통계표 그림(`2-9`), 질문별 EDA 4패널(`3-5`), EDA 결과표 그림(`3-6`). 새 분석 없음(기존 집계를 질문별로 다시 묶음).
- 수치 바로잡음: 관외출동은 같은 거리(6km 이하)에서 **+4~9%p**(기존 "+4~10%p"), 거리 구간은 "1km 이하 19~27% → 4~6km 85~94%".
