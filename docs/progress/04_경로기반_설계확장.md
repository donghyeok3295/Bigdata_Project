# 04. 구급차 경로 기반 설계 확장 (팀 검토 대기)

날짜: 2026-10-15

전제: 기업튜터링 시연용 화면을 만들다가 "구 평균 정체만으로는 구급차가 실제로 지연되는 이유(경로상 정체, 우회, 특례)를 반영하지 못한다"는 문제가 제기됨. 데이터를 다시 확인해 설계를 확장했다. **규칙 7번·범위 변경이 포함되어 팀 합의 전까지 초안이다.**

---

## 끝낸 것

### 1. 데이터 재확인

- 차량통행속도 원본(`work/speed/speed_20XX.parquet`)은 구 단위가 아니라 **도로 링크 단위 시간별 속도**다. 2024년 1,856,274행, **5,083링크·513개 도로**. 컬럼: 일자, 요일, 도로명, 링크아이디, 시점명, 종점명, 방향, 거리, 차선수, 기능유형구분, 도심/외곽구분, 권역구분, 01~24시
  - 기능유형: 보조간선 770,333 / 주간선 546,067 / 기타 444,661 / 도시고속 95,213행 → **골목·이면도로는 없음**
  - 구별 링크 수 98~389개(중앙값 184)
- 구급 기록에는 신고·출동·현장도착 시각, 대원 기재 거리, 신고 구가 있고 좌표·동은 없다
- 센터 참조표에는 주소와 관할구역(동 목록, 자유 형식 텍스트)이 있다

### 2. 설계 결정 (D-010 초안)

- **역추적**: 센터에서 도로 거리 `dist_km ± 0.5` km 띠 ∩ 신고 구 → 신고 위치 후보 30개
- **피처**: 후보까지 구급차 이동 시간의 평균·퍼짐·결측 (`route_eta_min`, `route_eta_spread`, `route_missing`)
- **모델 G6** = G4 + 경로 피처, D+ 전용. G4 대비 ΔBrier·Δlog loss 검정 → RQ4
- **절대 규칙 7 수정**: 학습·보정되지 않은 경로 정보만 사후 결합 금지. 경로 정보는 G6 피처로만 확률에 들어감
- **학습·서비스 동일 함수**: 서비스 피처도 역추적 함수로 생성, 입력 좌표까지 실제 경로는 화면 설명용
- 추가로 필요한 데이터는 **표준노드링크 1종**(TOPIS 링크ID를 도로망에 연결)

### 4. 시연용 목업 (`mockup/`, 커밋 안 함)

- 센터 비교·운영 대시보드·파이프라인 3탭, 목업 데이터. 자문 피드백 반영 전 상태로 맞춤
- 신고 위치 주소 입력, 접수 시각 자동(현재 시각), 활동량 슬라이더 제거, 도로를 따라가는 참고 경로(목업 한정 OSRM 데모 서버)
- **D-010 화면 반영 완료**: G6 확률 + 구급차 예상 도착 시간(접수·출동 준비 + 주행 + 교통 지연 − 특례), 도로별 현재 속도 색 경로, 일반 차량 경로 대비 우회 표시, 병목 구간 라벨, "가장 가까운 센터가 몇 위인 이유" 박스, D+/D− 토글 제거
- 센터는 공개 주소(15157581)를 OSM Nominatim으로 좌표 변환한 **실제 119안전센터 위치**(119곳 중 108곳 사용, 변환 실패 4·구 불일치 7 제외). 출동 건수·확률·도로 속도는 가상 값
