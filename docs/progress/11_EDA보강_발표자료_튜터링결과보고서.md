## 끝낸 것

### 1. EDA 보강과 그래프 정리
- 모델 결과로 만든 분석(정보 그룹 기여도, 조정 오즈비)은 **EDA가 아니라서 삭제**했다(사용자 지적). EDA는 원본 EMS 데이터를 정제·전처리한 뒤 **데이터 분석만으로** 프로젝트 질문에 답하는 것으로 한정한다.
- `notebooks/07_중간발표_EDA_보강.ipynb`(신규): 원본 `work/seoul_2024_raw.csv`에서 정제 규칙별 제외 건수(9,672 / 25,099 / 118 / 363 → 550,251, 문서 값과 일치), 결측률, 거리 이상치, 거리×시간대·관외, 구별 관외, 거리×강수, 구×시간대·연도.
- 새로 알게 된 것: **복귀 일자(`cbk_ymd`)는 `\N`이 아니라 공백 8칸 문자열**이다. 공백도 결측 처리해야 한다(규칙 5절과 일치, 발표 전처리 사례로 사용).
- 그래프는 **16개로 선별**해 단계별 폴더로 정리했다: `1_전처리`(3) / `2_일변량`(7) / `3_다변량`(4) / `4_모델결과`(2). 겹치거나 안 쓰는 그래프(09_dist, 10_near_hour, 20_outofjur, 05_강수, 01 깔때기, 08_sido, 04_center_only, Q4, 17, 18)는 발표자료에서 뺐다. `eda/` 원본 PNG는 문서 참조가 있어 유지.
- **대상이 그래프마다 다르다**: 제안발표 단계 EDA(2-1, 2-2, 2-4~2-6, 3-4)는 **서울 2024 전체 코호트(조직 유형 혼합)**, 나머지는 **안전센터 코호트**. 슬라이드·보고서에 구분 표기.
- 노트북 06·07은 전체 산출물을 `work/figures/`·`work/tables/`(커밋 제외)에 만들고 **선별본만** 발표자료 폴더로 복사한다. 그림 4-1의 "D−"는 글꼴에 없어 "D-"로 바꿨다.

### 3. 기업 튜터링 결과보고서 (PDF 수정 단계)
- 양식: 결과보고서는 **자유양식, 최소 10페이지**. 저번 학기 「기업튜터링_최종결과보고서_러닝머신.pdf」의 목차·형식을 따랐다(표지 → 목차 → 1 개요 → 2 데이터셋·EDA → 3 시스템 설계·구현 → 4 실험 결과 → 5 월별 활동 → 6 자문 반영 → 7 학습 성과 → 8 미비한 점 → 9 결론·소감).
- 초안 PDF: `기업튜터링/자료/기업튜터링_최종결과보고서_파이프라이너스.pdf` (25쪽, 그림 17개).
- **다시 만드는 법**: `기업튜터링/05_최종결과보고서.md` 수정 → `py -3.12 기업튜터링/make_report_pdf.py` (Chrome 헤드리스로 HTML → PDF, 그림은 `기업튜터링/발표자료/그래프/`에서 읽음). 그림 칸 문법: `> [그림 x-y] \`상대경로\` — 캡션`, 빈 칸은 `> [사진] …`, `> [캡처] …`, 팀이 채울 곳은 `[팀 작성]`(노란색 표시).
- **작성 원칙(사용자와 합의, 방법 1)**: 결과 요약서·활동일지의 구성·문장·수치를 따르되, **실제로 하지 않은 구현은 "학습·설계·목업"으로 적는다.** 하지 않은 구현을 완료로 쓰는 것은 하지 않는다(지도교수 서명으로 사업단에 제출되는 공식 기록). 사용자가 "두 문서에 그대로 맞춰 달라"고 했을 때 이 이유로 방법 1(사실 기반) / 방법 2(빠진 것을 실제로 구현한 뒤 쓰기)를 제안했고 **방법 1로 진행**했다.
- 실제 구현 상태(판정 기준): 구현 = HDFS 저장, Spark 7년치 정제, EDA, 강수 결합, G0 1차 모델·보정(보정 그래프 포함), pytest 51·ruff. 목업 = 센터 비교 화면·운영 대시보드(가상 값), '연구용 참고 정보' 문구, 평소값 대체·경고. 학습·설계 = 공공 API 수집기, Docker Compose, GitHub Actions, kind/K8s, 전체 통합 실행, Docker 재시작, 3층 활동량 계산, pandas vs Spark 비교.
