## 끝낸 것

### 1. 관할구역 정리

- `src/spatial/jurisdiction.py`: 관할구역 문장 → `[{dong, parent, partial}]`
  - 묶음 표기 펼치기(`가양2ㆍ3동`, `을지로3∼7가`, `반포본ㆍ2동`), 괄호 안 행정동, 쉼표 빠진 문장(마곡), 닫는 괄호 누락(반포) 처리
  - 번지·"일부"·"제외" → `partial`. '중계동'·'송중동'의 '중'은 partial로 보지 않음
  - `find_centers(sgg, dongs, table)`: 구 + 동 이름(행정동 → 법정동 추정 포함)으로 관할 센터 후보
- `tests/test_jurisdiction.py` 5개 통과. **pytest·ruff가 설치돼 있지 않아** 테스트 함수를 직접 호출해 확인했다
- 결과 `work/ref/center_jurisdiction.csv`: 608행, 580개 동(구+이름), 119개 센터 모두 1행 이상
  - 2곳 이상이 맡는 동 26개 — **전부 번지·"일부" 단위 분할**(예: 서초1~3동, 구로2동, 이문1동, 목5동). 행정동 기준으로 나뉜 동(신림동, 봉천동, 자양동 등)은 모두 1곳으로 정해짐

### 2. 목업 반영 (`mockup/`, 커밋 안 함)

- `/compare` 목업 응답에 `location.hdong`·`bdong`, `jurisdiction`, `candidates[].is_jurisdiction` 추가. 후보 = 가까운 5곳 + 관할 센터
- 동 판정: 목업은 Nominatim 역지오코딩(suburb=행정동, quarter=법정동), 실제 백엔드는 카카오 좌표 → 행정구역
- 목업의 구 경계(2013 단순화본)가 경계 부근에서 틀려 역지오코딩의 구를 우선하도록 수정(강남역이 서초구로 잡히던 문제)
- 화면: "관할 센터 · 기본 출동" 카드 고정(빨간 테두리) → "다른 후보 · 확률순". 관할보다 확률 높은 후보 수, "관할 센터가 n위인 이유", 번지 분할 동 안내, 위치 정보 없는 관할 센터 안내
- 확인: 잠실역→잠실센터, 노원역→상계센터, 신림역→신림센터(2위, 이유 표시), 서울역→회현센터, 구로디지털단지역→공단센터, 강남역→역삼센터, 상일동 부근→강일·고덕 후보 2곳
