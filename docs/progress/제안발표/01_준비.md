## 이번 단계에서 끝낸 것

### 1. 구급 데이터 확보·정제·EDA
- 서울 2024년 구급 현황 추출: 585,503건 → 정제 550,251건 (94.0% 유지)
  - 제외: 취소 9,672 / 도착기록 없음 25,099 / 0분 이하 118 / 180분 초과 363
- 산출물: `work/seoul_2024_raw.csv`, `work/seoul_2024_clean.csv`
- EDA 그래프 (`eda/02~10_*.png`):
  - 8분 초과율 47.9% (평균 8.79분, 중앙값 8.00분)
  - 시간대×요일 초과율 35~57%
  - 센터별 초과율 29~74%, 조직유형별(센터 48.8 / 현장대응단 30.2 / 구조대 41.2)
  - **구 단위 활동량별 초과율 41.5% → 57.4% 단조 증가 (15.9%p)** — RQ1-a 핵심 근거
  - 센터 단위 활동량은 경향 없음(47.6~49.8%) — 인접 센터 교차 출동으로 해석
  - 연도별 초과율 21.2%(2019)~51.8%(2025), 전국 대비 서울 17개 시도 중 3위(56.4%)
  - 거리 중앙값 2km, 상위 1% 6km → `dist_out_of_range_km = 6`
- 상세: `docs/06_EDA_결과.md`

### 2. 차량통행속도(교통) 데이터 확보·전처리
- TOPIS 도로·일자별 통행속도 월별 xlsx, **2019~2025년 전체** 확보 (`raw/speed/<연도>/`)
- 연도별 병합 → `work/speed/speed_2019~2025.parquet` (7개)
  - 작업 중 2024·2025 파일 대부분의 시간 컬럼 표기(`~01시`)가 다른 연도(`01시`)와 달라 병합 시 컬럼이 갈라지는 버그를 발견·수정 (`notebooks/02_속도데이터_병합.ipynb`)
- 구(sgg) 매핑 확인: 속도 데이터 `권역구분`과 EMS `sgg_nm`이 **25개 구 완전 일치** — 별도 매핑표 불필요
- 구·시간 평균 속도 집계(`speed_hist`) → `work/speed/speed_by_gu_hour.parquet` (1,524,000행) (`notebooks/03_속도_구시간평균.ipynb`)
- 데이터 품질 이슈 발견: 2020년 12월 원본 자체가 12/14일까지만 있고 이후 17일 결측 (원본 결함, 우리 코드 문제 아님)

### 3. EDA ⑧ — 정체 구간별 8분 초과율 (RQ2 근거)
- EMS 코호트(2024)와 `speed_by_gu_hour`를 "구 + 신고 시각 직전 완결 시간"으로 결합 (누출 없이 진행)
- 결과: 속도 5분위 Q1(정체) 50.9% → Q5(원활) 44.5%, **단조 감소, 스프레드 6.4%p**
- 정체와 지연 사이 연관성 확인 → **RQ2(정체 지수) 그대로 진행 결정**
- 산출물: `notebooks/04_EDA_정체구간.ipynb`, `eda/11_speed_cong.png`
