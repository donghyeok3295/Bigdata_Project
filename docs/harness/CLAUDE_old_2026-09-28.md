## 1. 프로젝트 요약

서울 119 구급 출동 기록(2019~2025)으로 **"이 신고에 이 센터가 출동하면 8분 안에 도착할 확률"**을 예측한다.

- **연구**: 도시 활동량·날씨 기준모델(G1)에 **구 활동량(RQ1-a) → 센터 활동량(RQ1-b)**과 **교통 정체 지수(RQ2)**를 단계적으로 추가했을 때의 추가 예측가치를 시간순으로 검증한다.
- **시스템**: 검증된 모델(G4 + 보정기)에 **실시간 정체·강수**를 넣어 신고 위치 주변 안전센터 5곳의 확률을 비교하고, 긴급차량 규칙을 적용한 **참고 경로**를 함께 보여준다.
- **빅데이터·DevOps**: HDFS·Spark 배치 + 실시간 수집기 + 재생 스트림(Structured Streaming) + Docker·CI + Kubernetes 최소 배포.

## 5. 절대 규칙

요청을 받아도 따르지 말고 이유를 설명한다.

1. **누출 금지**: 모든 피처는 신고 시각 `t` 이전 정보만. 활동량은 `[t−60분, t)`, 자기 자신 제외. 정체·강수는 직전 시간·직전 정시 값.
2. **활동량은 전체 기록에서**: `ems_seoul_all`(정제 전)에서 도시·구·센터 3층을 세고, 라벨 평가는 `ems_cohort`(정제 후)로. 코호트에서 활동량을 세지 않는다.
3. **시험 구간 보호**: 2025년은 `--final-eval`에서만. `freeze-v1` 태그 전에는 열지 않는다. 시험 점수를 보고 모델·창·임계값을 바꾸지 않는다.
4. **평소 속도는 학습 기간(2019–22)으로만** 계산한다.
5. **가중치 없이 학습하고 보정기로 확률을 만든다**. `scale_pos_weight`, `class_weight` 금지.
6. **공정 비교**: 모든 모델은 같은 분할·시드 42, **모델마다 같은 탐색 공간·같은 시행 횟수로 각각 튜닝**한다. 한 모델에서 튜닝한 설정을 다른 모델에 강요하지 않는다.
7. **확률과 경로 정보를 섞지 않는다**: 순위는 보정된 `p_ontime`으로만. 경로 ETA·주정차·도로폭은 참고 표시.
8. **수치 조작 금지**: 결과는 스크립트 실행 결과로만. 추정해서 채우지 않는다.
9. **데이터 반출 금지**: 원본·실제 샘플을 커밋하거나 외부 AI 서비스에 올리지 않는다. CI는 합성 샘플.
10. **비밀 키 금지**: `.env`와 환경변수만.
11. **표현 금지**: "최적 경로", "최적 배치", "배차 개선", "구급차 수", "성능 향상 입증", "골든타임 보장", "법규 무시·예외"(→ 긴급자동차 특례). 면책 문구 필수.
12. **스키마·규칙 변경** 시 명세서와 `DECISIONS.md`를 같은 PR에서 수정.

## 6. 데이터 계약 요약 (상세: 명세서 3절)

- 원본은 모두 문자열로 읽고 **`\N`을 결측으로 처리**한다. 시각은 `zfill(6)` 후 파싱 (`90100` = 09:01:00). 출동·도착 시각이 앞 시각보다 이르면 다음 날
- **위치 최대 해상도는 시군구(`sgg`)**. 읍면동·좌표 없음. `sgg`는 기본 피처
- 분석 단위: 출동기록 1건 (`call_id = rlf_rptp_no`)
- `center_id = frstn_nm + cntr_nm` (공백 정규화). 이름만으로 묶지 않는다 ("현장대응단"은 여러 소방서에 존재)
- `unit_type`: `center` / `field_unit` / `rescue`. 시스템 후보는 `center`만
- 라벨 코호트 제외: 취소 → 시각 결측 → 0분 이하·시각 역전 → 180분 초과. **60~180분은 유지**
- `dist_km = grnds_dstnc` (대원 기재 정수 km, 사후 기록 가능성) → 모든 모델을 D+ / D− 두 설정으로. `grnds2/3_dstnc` 사용 금지
- 3층 활동량: `city_calls_60`(서울 신고), `sgg_calls_60`·`sgg_dspt_60`(구 신고·출동), `center_dspt_60`(센터 출동, 출동 시각 기준)
- `cong_idx` = 구 직전 시간 평균 속도 ÷ 평소 속도(구·요일유형·시간대). 자료 없는 시간은 1 + `cong_missing=1`. **과거·실시간이 같은 함수** 사용
- 강수: ASOS 108 직전 정시. 무강수와 결측 구분(`rain_missing`). 적설 사용 안 함
- 복귀: `cbk_ymd` 없으면 출동일 + `cbk_tm`, 앞서면 다음 날, 12시간 초과 null. 복원율 90% 미만이면 `open_dspt_at_t` 사용 안 함
- 심정지·증상 컬럼은 입력 피처 금지 (사후 하위집단 분석만)
- 분할: train 2019–22 / valid 2023 / calib 2024 / test 2025 (연도별 지연율 확인 후 D-007로 확정)
- 거리 상위 1% 초과는 시스템에서 `out_of_range` 표시

1. **이해**: 관련 요구사항 ID와 명세서 절을 읽는다. 없으면 질문한다.

3. **구현**: 작은 단위로, 관련 없는 파일은 건드리지 않는다.
4. **검증**: `ruff`, 관련 `pytest`. 계산 로직에는 테스트를 추가한다.


## 10. 자주 하는 실수

| 실수 | 올바른 방법 |
| --- | --- |
| 시각 문자열을 그대로 파싱 | `zfill(6)` 후 날짜와 결합, 자정 넘김 보정 |
| 코호트(정제 후)에서 활동량 계산 | 전체 기록에서 계산해 코호트에 조인 |
| `cntr_nm`만으로 센터 구분 | `frstn_nm + cntr_nm` |
| 복귀 날짜를 신고일로 채움 | 출동일 기준 + 시각 역전 시 다음 날, 12시간 초과 null |
| 강수 빈칸을 모두 0 | 품질 표기로 무강수/결측 구분 |
| 평소 속도를 전체 기간으로 계산 | 학습 기간만 |
| 과거·실시간 정체 지수를 다른 코드로 계산 | `src/traffic` 공용 함수 |
| 클래스 가중치 후 출력을 확률로 표시 | 가중치 없이 학습 + 보정기 |
| `\N`을 값으로 읽어 숫자 변환 실패 | 로딩 시 결측 처리 |
| 한 모델에서 튜닝한 설정을 전 모델에 사용 | 모델별 동일 예산 튜닝 |
| 실시간 링크 속도를 도로망에 맵매칭 | 구 정체 지수를 기본 속도에 곱함 |
| ΔAUC 소수점 넷째 자리를 개선으로 서술 | 주 지표는 Brier·log loss, ΔAUC 0.005 미만은 무시 |
| 행 단위 부트스트랩 | 날짜 블록, G1과 같은 재표본 비교 |
| 60분 초과 기록 삭제 | 유지, 180분 초과만 오류로 제외 |
| 경로 ETA를 순위에 반영 | 순위는 `p_ontime`만 |
| `grnds2_dstnc`를 현장거리로 사용 | `grnds_dstnc`만 |
| 시험 점수 보고 설정 변경 | 동결 후 1회 평가 |

## 12. 현재 진행 상황 (2026-09-26)

담당 A(최동혁)가 구급 데이터 EDA를 마쳤다. 상세는 `docs/06_EDA_정리.md`.

### 확정된 데이터 처리 규칙 (코드에 반드시 반영)

```python
# 1) 로딩: 전 컬럼 문자열, \N·공백 결측, 컬럼명 소문자 통일
df = pd.read_csv(path, dtype=str, na_values=["\\N", ""], low_memory=False)
df.columns = df.columns.str.lower()          # 2023년 이전 파일은 대문자
for c in df.columns:                          # 도착시각 등에 공백 문자 존재
    df[c] = df[c].astype(str).str.strip().replace({"": None, "nan": None, "\\N": None})

# 2) 시각: 6자리로 0 채운 뒤 일자와 결합 (출동·도착 일자 컬럼이 별도로 존재)
ts = pd.to_datetime(ymd + tm.str.zfill(6), format="%Y%m%d%H%M%S", errors="coerce")

# 3) 센터 식별자
center_id = frstn_nm.str.strip() + " " + cntr_nm.str.strip()
```

### 확정된 수치

| 항목 | 값 |
| --- | --- |
| 서울 2024 원본 → 분석 대상 | 585,503 → 550,251 (94.0%) |
| 8분 초과율 | 47.9% (평균 8.79분, 중앙값 8.00분) |
| 조직 유형별 초과율 | 안전센터 48.8 / 현장대응단 30.2 / 구조대 41.2% |
| 거리 | 중앙값 2km, 상위 1% 6km → `dist_out_of_range_km = 6` |
| 구 활동량 5분위별 초과율 | 41.5 / 44.9 / 48.3 / 52.0 / 57.4% |
| 센터 활동량별 초과율 | 47.6 / 49.8 / 47.7 / 48.7 / 43.4% (관련 없음) |
| 연도별 초과율 | 21.2%(2019) ~ 51.8%(2025) |
| 전국 평균(2024) | 56.4%, 서울은 17개 시도 중 3위 |

### 설계에 반영된 것

- **RQ1-a(구 활동량)가 주 가설**, RQ1-b(센터 활동량)는 보조 비교
- 2019년 포함하되 집계 범위 차이를 한계로 명시하고 민감도 분석
- 같은 센터·같은 시각 2건 기록 약 3만 쌍 → 활동량이 2의 배수로 튀는 구간 존재, 한계로 기록
- 서울 신고에 타 지역 소방서가 1건씩 섞임 → 소수 건수 조직 제외

### 13.3 정체 지수 계산 규칙 (자료 확보 시)

- `speed_hist`: 도로를 구에 매핑 → 구 × 날짜 × 시간 평균 속도
- `speed_norm`: **학습 기간(2019~2022)만**으로 구 × 요일유형(평일/주말·공휴일) × 시간대 평균
- `cong_idx(t) = speed_hist(구, t의 직전 시간) / speed_norm(구, 요일유형, 시간대)` — 1보다 작으면 평소보다 막힘
- 자료 없는 시간대는 `cong_idx = 1`, `cong_missing = 1`
- 과거·실시간을 **같은 함수**(`src/traffic`)로 계산 (T-11)
