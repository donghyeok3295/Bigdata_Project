## 1. 프로젝트 개요

과거 서울 119 구급 출동 기록으로 **"이 신고에 이 센터가 출동하면 8분 안에 도착할 확률"**을 예측하는 모델을 만들고, 이 모델에 **실시간 교통 정체와 날씨**를 넣어 신고 위치 주변 센터들의 위험을 비교해 주는 시스템을 구축한다. 시스템은 긴급자동차 특례를 반영한 **참고 경로**를 함께 보여준다.

| 구분 | 연구 (모델) | 시스템 (시연) |
| --- | --- | --- |
| 하는 일 | 지역·센터 활동량과 교통 정체가 8분 초과 위험 예측에 주는 **추가 예측가치를 검증** | 신고 위치 주변 안전센터 5곳의 8분 내 도착 확률 비교 + 참고 경로 |
| 근거 | 과거 실제 도착 기록, 시간순 분할 | 검증된 모델에 실시간 데이터를 입력 |
| 논문에서의 위치 | **결과 (주장하는 부분)** | **응용 구현 (보여주는 부분)** |

### v15 추가 변경 — 구급차 경로 기반 예상 시간 (2026-10-15, 팀 합의 완료, D-010)

- **확인 사항**: 차량통행속도 원본은 구 단위가 아니라 **도로 링크 단위 시간별 속도**다(2024년 5,083링크)
- **역추적 도입**: 신고 좌표는 없지만 센터 위치 + 대원 기재 거리 + 신고 구로 "센터에서 도로 거리 d±0.5km 띠 ∩ 신고 구"를 신고 위치 후보로 본다
- **모델 G6 추가**: 후보까지의 구급차 예상 이동 시간(링크 속도 + 긴급자동차 특례)을 피처로 넣는다. D+ 전용
- **시스템**: 센터별 구급차 예상 시간(분), 지연 요인 분해, 우회 경로 표시
- **범위 변경**: 링크 정적 매칭을 필수로, 불법주정차·신호교차로·생활인구·관할 동 범위 축소는 향후 계획으로
- **관할 센터 표시 (D-011)**: 출동 관례상 관할 센터가 먼저 출동하므로, 화면에서 신고 지점의 **동 단위 관할 센터를 기준선으로 고정**하고 다른 후보를 확률 순으로 비교한다. 확률·순위는 바꾸지 않으며 모델 입력에도 쓰지 않는다

### v15 변경 (EDA 결과 반영)

서울 2024년 EDA와 7년 연도별 확인을 마쳤다(`06_EDA_결과.md`). 반영 사항은 다음과 같다.

- **RQ1 우선순위 조정**: 예비 분석에서 센터 활동량은 효과가 없었고(47.6~49.8%) 구 활동량은 뚜렷했다(41.5→57.4%). RQ1-a(구 단위)를 주 가설로, RQ1-b(센터 단위)를 보조로 둔다
- **거리 기준 확정**: 중앙값 2km, 상위 1% 6km → `dist_out_of_range_km = 6`
- **데이터 로딩 규칙 확정**: 연도별 컬럼명 대소문자 차이, `\N`·공백 결측, 시각 6자리 보정
- **제외 규칙 실측 확정**: 585,503 → 550,251건(94.0% 유지)
- **2019년 포함 결정**: 집계 범위 차이는 한계로 명시하고 민감도 분석으로 확인
- **서울 선정 근거 확보**: 전국 평균 56.4%, 서울 47.9%로 17개 시도 중 3위

### v13 → v14 변경

- **위치 해상도 확정**: 데이터에 읍면동·좌표가 없고 **시군구(구)가 최대 해상도**임을 확인. 지역 조건은 구 단위로 반영
- **부하를 3층으로 재설계**: 도시 → **구** → 센터. 관할 센터가 바쁠 때 인접 센터가 출동해 센터 활동량이 낮게 기록되는 문제를 보완
- **기준선 B0 추가**, 튜닝은 **모델별 동일 예산**으로 변경 (G4 튜닝 후 공유하던 방식은 편향)
- **보정 지표 격상**: Brier와 함께 calibration slope·intercept를 주 결과로. 주 비교 지표는 ΔBrier·Δlog loss, ΔAUC는 보조
- **연도 민감도**: 코로나(2020~21)와 2024년 지연율 이상 여부를 확인해 보정 구간을 조정
- **Velocity 보강**: 1주차부터 실시간 교통·기상 수집기를 가동해 실제 시계열 확보, 재생 스트림은 보조
- **Kubernetes 최소 배포 추가** (강의 필수 항목 누락 보완), 실시간 링크 맵매칭은 제외
- 표현 정리: "골든타임 8분" → "8분 응답 기준", "법규 예외" → "긴급자동차 특례"

## 2. 선정 배경과 문제 정의

심정지처럼 시간이 결정적인 환자에게 구급대의 빠른 도착은 중요하다. 2024년 전국 구급대는 3,324,287회 출동해 1,790,794건을 이송했다(e-나라지표). 그러나 공개 통계는 지역별 평균 도착시간만 보여줄 뿐, **개별 신고가 기준 시간을 넘길 위험**이나 **그 순간 어느 센터가 유리한지**는 알려주지 않는다.

**현황 (EDA 확인 완료)**: 서울 2024년 분석 대상 550,251건 중 신고~현장도착 **8분 초과 비율은 47.9%**(평균 8.79분, 중앙값 8.00분)다. 시간대별로는 새벽 약 35%에서 평일 출퇴근 약 57%까지, 안전센터별로는 29%에서 74%까지 차이가 난다. 출동 거리가 2km 이하인 근거리 건만 봐도 시간대에 따라 28.2%~43.7%로 달라져, 지연의 원인이 거리보다 동적 요인에 있음을 시사한다.

**8분 기준**: 본 연구는 **8분 응답 기준(신고 → 현장도착)을 연구 기준값**으로 채택한다. 이 기준은 심정지 소생 연구에서 유래해 국제적으로 널리 쓰이지만(원문 확인 후 인용), 의학적 골든타임 확보나 생존율 보장과 같은 뜻이 아니다. 외상 등 다른 질환에서는 적정 기준이 다를 수 있다.

**활용 장면**: 119 종합상황실이 신고 접수 시 주변 센터별 지연 위험을 참고하는 장면, 소방 정책 담당자가 구·시간대별 위험을 파악하는 장면.

## 3. 연구 질문과 목적

### 3.1 연구 질문

같은 서울 데이터, 같은 모델(LightGBM), 같은 시간순 분할에서 **신고 시점에 알 수 있는 정보만** 사용한다.

- **RQ1 (활동량의 공간 단위, 주 가설)**: 도시 전체 활동량에 **신고 지역(구) 활동량**과 **출동 센터 활동량**을 단계적으로 추가하면 8분 초과 위험의 예측 성능과 확률 신뢰도가 개선되는가? 예비 분석에서 구 단위는 뚜렷한 관련(41.5→57.4%), 센터 단위는 관련이 없었다(47.6~49.8%). 따라서 **RQ1-a(구 단위)를 주 가설로, RQ1-b(센터 단위)를 보조 비교**로 둔다.
- **RQ2 (교통 정체)**: 신고 지역의 **교통 정체 지수**를 추가하면 개선되는가?
- **RQ3 (결합과 조건)**: 둘을 함께 넣으면 추가로 개선되는가? 고부하·강수·정체 시간대에서 효과가 달라지는가?
- **RQ4 (경로 기반 예상 시간, 확장)**: 구 평균 정체 지수 대신 출동 경로의 **도로별 속도와 구급차 특례**로 계산한 예상 이동 시간을 추가하면(G6) G4보다 개선되는가? (D+ 한정, D-010)

RQ1을 두 단계로 나눈 이유: 관할 센터가 바쁘면 인접 센터가 출동하고 기록에는 **인접 센터**가 남으므로, 출동 센터의 활동량만 보면 지역 포화 상태를 놓친다. 구 단위 활동량이 이 부분을 담당한다.

### 3.2 목적

1. **연구**: RQ1~3을 과거 실제 기록으로 검증한 소논문
2. **시스템**: 검증된 모델에 실시간 정체·날씨를 입력해 센터별 위험을 비교하고, 긴급자동차 특례를 반영한 참고 경로를 보여주는 웹 시스템
3. **빅데이터·DevOps**: HDFS·Spark 배치, 실시간 수집·스트림 처리, Docker·CI/CD·Kubernetes 최소 배포

### 3.3 측정 가능한 목표

- 기준모델(G1) 대비 각 확장 모델의 **ΔBrier·Δlog loss·ΔAUC**와 날짜 블록 부트스트랩 95% 신뢰구간 보고 (개선 여부와 무관하게 보고)
- 보정 품질: calibration slope 0.8~1.2, reliability diagram 제시
- 센터별 위험 비교 응답 3초 이내(LLM 제외)
- 실시간 수집 파이프라인 10주 가동, 스트림 처리량·반영 지연 측정
- 6~8쪽 소논문

**차이점**
1. 평균 도착시간 회귀가 아니라 **개별 신고 단위의 8분 초과 확률**을 예측하고, **확률 보정 품질**을 주 결과로 제시
2. 활동량의 **공간 단위(도시·구·센터)**와 **교통 정체**의 추가 예측가치를 같은 데이터·모델에서 분리 비교
3. 검증된 모델을 **실시간 데이터로 구동하는 시스템**까지 연결

"국내 최초"는 주장하지 않는다. 필요하면 "확인된 범위에서"를 붙인다.

| `grnds_dstnc` | 출동 칸 "거리 km": 대원이 기재한 출동 위치 → 현장 거리 | 사후 기록 가능성 → **거리 포함(D+)·제외(D−) 두 설정**으로 검증 |
| `grnds2_dstnc`, `grnds3_dstnc` | 1·2차 이송 거리 | 사용하지 않음 |
| `ctpv_nm`, `sgg_nm` | 시도, 시군구 | **위치 최대 해상도는 시군구**. 읍면동·좌표 없음 |
| `frstn_nm` + `cntr_nm` | 소방서 + 출동 조직 | **둘을 합쳐 `center_id`**. "현장대응단"은 여러 소방서에 같은 이름으로 존재 |
| `trmn_se_nm` | 종결 구분 | 취소 건은 라벨 평가에서 제외(활동량 계산에는 포함) |
| `hrtarst_nm`, `ptn_sym_se_nm` | 심정지, 증상 | 현장 기록일 수 있어 **입력 피처로 쓰지 않음**. 사후 하위집단 분석만 |

**결측 표기**: 원본의 결측은 `\N` 문자열로 저장되어 있다. 로딩 시 결측으로 처리한다.

**분석 단위**는 출동기록(구급보고서) 1건이다. 신고 1건이나 차량 1대와 같다고 보지 않는다.

## 6. 방법: 위험 예측 모델 (연구)

### 6.1 라벨과 평가 대상

- `resp_min` = 신고 → 현장도착(분), `y_late` = 8분 초과면 1
- 라벨 코호트: 취소 건, 시각 결측·역전, 명백한 입력 오류(180분 초과)만 제외. **60~180분 장시간 기록은 유지**하고 상한 민감도를 보고

### 6.2 피처 (모두 신고 시점 t 이전 정보)

| 그룹 | 피처 | 계산 기준 |
| --- | --- | --- |
| 기본 | `center_id`, **`sgg`(신고 구)**, 시간대, 요일, 월, 공휴일, 조직 유형 | 신고 일시 |
| 기본 | **`out_of_jur`(관할 일치 여부)** = 신고 구 ≠ 출동 센터 소속 구 | 센터 주소에서 구 추출(정적). 신고 시점에 계산 가능 |
| 거리 (D+ 설정) | 현장거리(정수 km) | 원본 기재값 |
| 도시 활동량 | 서울 전체 직전 60분 신고 건수 | **정제 전 전체 기록** |
| **구 활동량 (RQ1-a)** | 신고 구의 직전 60분 신고 건수·출동 건수 | 정제 전 전체 기록 |
| 센터 활동량 (RQ1-b) | 같은 센터의 직전 60분 출동 건수 | 정제 전 전체 기록, 출동 시각 기준 |
| 교통 정체 (RQ2) | 신고 구의 정체 지수 = 직전 시간대 평균 속도 ÷ 평소 속도(구·요일유형·시간대) | 평소 속도는 학습 기간으로만 계산 |
| 날씨 | 직전 정시 1시간 강수량, 결측 표시 | ASOS 108 |
| 복귀 전 출동기록 (조건부) | 같은 센터에서 출동 후 복귀 전인 기록 수 | 복원 가능률 90% 이상일 때만 |

### 6.3 비교 실험

| 모델 | 입력 | 역할 |
| --- | --- | --- |
| 단순 기준 | 학습 기간의 센터×시간대 지연율 | 최소 기준 |
| **B0** | 거리만, 로지스틱 회귀 | 거리 기반 최소 기준 |
| LR | 기본 피처, 로지스틱 회귀 | 전통적 통계 기준 |
| G0 | 기본 피처, LightGBM | 알고리즘 효과 |
| G1 | G0 + 도시 활동량 + 날씨 | **주 기준모델** |
| **G2a** | G1 + 구 활동량 | **RQ1-a** |
| **G2b** | G2a + 센터 활동량 | **RQ1-b** |
| G3 | G1 + 정체 지수 | **RQ2** |
| G4 | G1 + 구·센터 활동량 + 정체 지수 | **RQ3**, 시스템에 쓰는 모델 |
| G5 | G4 + 복귀 전 출동기록 | 조건부 |

모든 모델을 **거리 포함(D+)·제외(D−)** 두 설정으로 학습해 결론이 일치하는지 확인한다. 튜닝은 **모델별로 같은 탐색 공간·같은 시행 횟수**를 쓴다(특정 모델에서 튜닝한 설정을 공유하지 않는다).

`out_of_jur`는 **기본 피처에 포함**되므로 G0부터 모든 모델이 함께 사용한다. RQ1·RQ2의 추가 예측가치는 G1 대비 **차이(Δ)**로 재기 때문에, 모든 모델에 동일하게 들어가는 피처는 기존 비교 구조를 바꾸지 않는다. 관외출동 자체를 별도 연구 질문으로 승격하지 않는 이유는, 이것이 우리가 세운 가설이 아니라 **지적을 받아 확인한 통제 변수**이기 때문이다 (D-008).

### 6.4 데이터 분할과 확률 보정

| 구간 | 기본 | 용도 |
| --- | --- | --- |
| 학습 | 2019~2022 | 모델 학습 |
| 검증 | 2023 | 조기 종료, 하이퍼파라미터 |
| 보정 | 2024 | 확률 보정기 학습, 경보 임계값 |
| 시험 | 2025 | **최종 평가 1회** |

**연도 민감도**: EDA에서 연도별 8분 초과율을 먼저 확인한다. 코로나 기간(2020~21)이나 2024년이 뚜렷하게 다르면 보정 구간을 2023년으로 옮기고 검증을 2022년으로 당기는 등 분할을 조정하고 근거를 기록한다.

클래스 가중치를 쓰지 않고 학습한 뒤, 보정 구간으로 확률 보정기(isotonic 또는 Platt)를 학습해 모델과 함께 저장한다.

### 6.5 평가

- **확률 품질 (주 지표)**: Brier score, log loss, **calibration slope·intercept**, reliability diagram. 보정 전후 비교
- **구분 능력**: ROC-AUC, 평균정밀도(AP)
- **실용성**: 보정 구간에서 "위험 상위 20% 경보" 임계값을 정해 시험 구간에 고정 → 재현율, 정밀도, 경보 건수, 놓친 지연 건수
- **추가 예측가치**: G1 대비 ΔBrier·Δlog loss·ΔAUC와 **날짜 블록 부트스트랩** 1,000회 95% 신뢰구간(주 단위 블록 민감도 병행). ΔAUC 0.005 미만은 실질적 차이로 해석하지 않는다
- **조건별**: 사전 지정한 고부하(구·센터 활동량 상위 20%, 학습 기간 기준), 강수, 정체 하위 20%, 출퇴근. 표본 수·지연 건수와 함께 제시
- **민감도**: 라벨 상한(60·120·180분), 활동량 창(30·60·120분, 여유 시)
- **해석**: SHAP 요약

## 7. 시스템: 실시간 센터별 위험 비교 (응용 구현)

### 7.1 동작

1. 사용자가 지도에서 신고 위치를 찍거나 주소를 입력한다.
2. 해당 지점이 속한 **구와 동**(법정동·행정동)을 확인하고, 가까운 **안전센터 5곳 + 관할 센터**를 후보로 고른다(현장대응단·구조대 제외). 관할 센터는 센터별 관할구역(동 목록)으로 판정한다(D-011).
3. 센터마다 모델에 입력한다: `center_id`, `sgg`, 현재 시각, **실시간 강수**, **실시간 정체 지수**, 구·센터 활동량(실시간 수집 또는 슬라이더), 거리(D+ 모델일 때 **센터 → 찍은 지점**의 도로 최단거리를 정수 km로). G6이면 **실시간 링크 속도로 계산한 경로 예상 시간 피처**(학습과 같은 역추적 함수)를 함께 넣는다.
4. 보정된 확률로 **순위**를 매긴다.
5. 각 센터에서 현장까지 **구급차 경로**(우회 포함)를 계산해 지도에 그리고, 예상 시간(분)과 지연 요인 분해를 보여준다.
6. 화면은 **관할 센터를 기준선으로 맨 위에 고정**하고, 나머지 후보를 확률 순으로 보여준다. 관할보다 확률이 높은 후보가 있으면 그 수와 "관할 센터가 n위인 이유"를 함께 표시한다. 번지·일부 단위로 나뉜 동은 관할 후보를 모두 고정한다.

관할 센터 고정은 **표시 방식**이다. 확률과 순위는 모델 결과 그대로이며, 실제 출동 결정은 상황실이 한다. 학습 데이터에는 신고 동이 없으므로 동 단위 관할은 모델 입력에 쓰지 않고, 모델에는 구 기준 `out_of_jur`를 그대로 넣는다.

지역 조건(정체·활동량)은 구 단위로 들어가고, 센터 간 차이는 **거리와 경로 예상 시간(G6)**이 만든다. 학습 데이터의 거리 분포 **상위 1%를 넘는 센터**는 "학습 범위 밖"으로 표시하고 순위 해석에 주의를 표기한다.

### 7.2 구급차 경로 규칙

| 규칙 | 내용 |
| --- | --- |
| 도로 속도 | **TOPIS 링크 속도**(실시간·직전 완결 시간). 링크 자료가 없는 도로는 도로 등급별 기본 속도 × 해당 구 정체 지수. 링크는 표준노드링크 형상으로 정적 매칭 (D-010) |
| 긴급자동차 특례 | 일방통행 역방향 통행을 허용하되 소요시간에 페널티 배수 적용. 법규 예외가 아니라 우선통행 특례이며 주의의무가 따른다는 점을 명시 |
| 부적합 도로 | 보행로·자전거도로·서비스 도로 제외 |
| 불법주정차 (향후 계획) | 경로 30m 이내 상습구역 수를 경고·지연으로 반영 |
| 검증 | 페널티 값을 바꿔 가며 경로가 어떻게 달라지는지 **민감도 분석** |

경로 정보는 **학습된 피처(G6)로만** 확률에 들어간다. 화면의 경로 예상 시간·요인 분해는 설명용이며 확률과 가중치로 사후 결합하지 않는다. "최적 경로"라고 부르지 않는다.

### 7.3 화면 예시

| 구분 | 센터 | 8분 내 도착 확률 (모델) | 구급차 예상 시간 | 지연 요인 | 주의 |
| --- | --- | --- | --- | --- | --- |
| **관할 (기본 출동)** | B센터 (가장 가까움) | 58% (2위) | 7분 40초 | 기본 4:10 + 교통 +3:30 (○○로 정체 우회) | 센터 직전 60분 출동 3건 |
| 다른 후보 | A센터 | 72% (1위) | 6분 10초 | 기본 5:00 + 교통 +1:30 − 특례 −0:20 | 관외 출동 |
| 다른 후보 | C센터 | 41% (3위) | 9분 20초 | 기본 7:40 + 교통 +1:40 | 학습 범위 밖(거리) |

상단 안내: "관할 센터보다 8분 내 도착 확률이 높은 후보 1곳 · 관할 B센터가 2위인 이유: 직전 60분 출동 3건, ○○로 정체"

하단: "연구용 위험 비교이며 실제 출동 지령에 사용하지 않습니다."

### 7.4 생성형 AI (수업 조건 확정 후)

필수로 정해지면 모델 확률·주요 요인·경로 경고만 입력해 설명 문장을 생성한다. 숫자·요인 방향 일치율과 근거 없는 문장 비율을 점검하고, 실패 시 템플릿으로 대체한다.

## 12. 한계

- 위치 해상도가 **시군구 단위**여서 지역 조건은 구 평균으로 반영되며, 같은 구 안의 위치 차이는 거리로만 구분된다.
- 같은 센터·같은 시각에 2건이 기록된 경우가 약 3만 쌍 확인되어, 활동량이 2의 배수로 튀는 구간이 있다.
- 2019년은 집계 조직 수(136개)가 2024년(189개)보다 적어 수집 범위가 달랐던 것으로 보인다. 포함하되 민감도 분석으로 확인한다.
- 현장거리는 대원이 기재한 정수 km이며 사후 기록일 수 있다(D+/D− 두 설정으로 검증).
- 활동량은 출동기록 기반 대리지표이며 실제 가용 차량 수가 아니다.
- 관외출동(신고 구 ≠ 센터 소속 구)은 전체 출동의 19.1%이며, 거리를 통제해도 8분 초과율이 7.7~9.6%p 높다. 다만 그 차이가 **지리 숙지도 때문인지, `grnds_dstnc` 기록이 관외 건에서 부정확하기 때문인지는 구분하지 못했다.** 지연이 출동 준비 단계가 아니라 이동 단계에서 발생한다는 것까지만 확인했다.
- 정체 지수는 구 단위 평균이고, 과거 자료와 실시간 자료의 도로 범위가 다를 수 있다. 경로상 다른 구·도로의 정체는 G6의 경로 예상 시간으로 보완한다(D-010).
- 경로 예상 시간의 신고 위치는 **역추적 후보 범위의 평균**이다. 기재 거리가 정수 km이고 사후 기록일 수 있어 D+에서만 쓰며, 같은 구 안의 다른 관할 출동도 구 단위로만 거른다.
- TOPIS 링크는 간선 위주(2024년 5,083링크)라 골목 구간은 등급 기본 속도로 채우고, 속도 해상도는 1시간이다. 긴급자동차 특례 효과는 개별 관측 없이 페널티 민감도로만 다룬다.
- 기상은 서울 단일 관측소 기준이다.
- 센터 비교 결과는 다른 센터를 보냈을 때의 실제 결과로 검증할 수 없다.
- 관할 센터 표시는 2022-11-30 기준 관할구역을 쓴다. 번지·"일부" 단위로 나뉜 동(26개)은 관할 센터 1곳을 특정하지 못해 후보를 모두 표시한다. 서울의 실제 출동 기준(관할 우선과 최근접 가용 차량의 비중)은 공식 자료로 확인해야 한다.
- 참고 경로는 GPS 궤적 없이 규칙으로 계산한 것이므로 최적성을 주장할 수 없다.
